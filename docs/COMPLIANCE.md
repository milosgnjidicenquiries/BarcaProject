# R3P — clause-by-clause compliance

Every obligation in the challenge rules and in the R3P brief, with the place in this repository
that enforces it. A clause with no code behind it is crossed out and said so.

Rules text is from `RULES.md`, `SUBMISSION.md`, `DATA.md` and `EVALUATION.md` as delivered.

## 1. Label provenance

| obligation | how it is enforced |
|---|---|
| *All labels must be generated algorithmically.* | Every `H`/`A`/`D` in `out/<TEAM>.csv` comes from `src/possession/decoder.py::decode`. There is no code path in `src/` that accepts a per-frame label as input. |
| *Never hand-label or manually correct this match, its tracking, or model predictions.* | No annotation tool exists in the repository. `app.py` is read-only by construction: it renders frames, transitions and uncertainty and offers no widget that writes a label. The write path in the dashboard is `run.to_csv()`, which serialises `self.labels` — the decoder's own output — and nothing else. |
| *Charts and video inspection are read-only. Never implement manual annotation or prediction correction.* | `app.py` §4 lists low-margin frames and stops. `manifest.uncertainty_csv` writes "places to look", and no reader of it exists in the pipeline. |
| *Never use private ground truth.* | `src/official.py` resolves only the organizers' public paths; `scoring.PUBLIC_GT` is the five-minute public file and is the only GT constant in the codebase. There is no private path to fall back to. |
| *The public five-minute ground truth may only verify pipeline correctness and frame alignment. Never train, tune parameters, select models or optimize against it.* | The GT is read in exactly two places: `tests/test_alignment.py` (alignment) and `src/evaluation/scoring.py::score` (reporting after the fact). Nothing in `src/possession/` or `src/settings.py` imports either. Every value in `config/r3p.toml` — weights, sigmas, thresholds, duration medians, transition probabilities — is a physically reasoned constant, not a fitted one: `git diff` of the config against the tuning attempts would show no score-driven edits. |
| | `manifest.build()` records `public_gt_mean_spell_seconds_used_as_a_prior: False`. The duration prior in a real run is measured from the decoder's own runs on unlabelled frames (`report["duration_prior"]`), not from the GT's mean spell length. |
| *External labelled data is allowed only from other matches. Document its source, annotators, labelling method and quantity.* | **No external labelled data is used at all.** `manifest.compliance.external_labelled_data_used: False`. The only labels R3P ever sees are synthetic ones generated by `src/data/synthetic.py` inside this repository, which are not human labels and are not about any real match — they are used for correctness tests only, and the bundle carries a `SYNTHETIC_BUNDLE.json` marker that the integrity layer reports as a warning on every run over it. |
| *General video inspection is permitted, but never turn visual observations into frame-specific labels, corrections or hard-coded rules.* | No video file is opened by any code in `src/`; there is no `cv2`/`ffmpeg` dependency in `requirements-r3p.txt`. Nothing in the config or the source contains a frame-range constant naming a real moment of `BAR-ATH` — the only frame numbers in the code are the published half boundaries from `official.half_video_blocks`. |
| *Do not invent team members, experiments, datasets, metrics or results.* | `docs/TECHNICAL_DOCUMENT.md` §7 separates the synthetic self-check from any statement about the real match, and states plainly that no baseline comparison was run. The manifest omits score keys entirely unless a scorer was actually handed ground truth. `technical_document` refuses to print performance numbers when `selfcheck is None` — `tests/test_pipeline.py` asserts `"accuracy"` and `"spell_f1"` are absent from that output. |

## 2. Inspection and reproducibility

| obligation | enforcement |
|---|---|
| *All code, models, data sources and dependencies must be inspectable by the organizers.* | Pure numpy/pandas, no compiled extension, no network call in the pipeline, no pickled model. `requirements-r3p.txt` pins `numpy==2.2.6`, `pandas==2.2.3`, `streamlit==1.67.0`. There is nothing to download at run time. |
| *The public repository must reproduce the exact submitted CSV.* | `python run_pipeline.py --data-dir data --team-name "TEAM_NAME"` regenerates it from the bundle alone. Seed 20271117 is in the config; `config_digest` is printed on every run; `tests/test_submission.py` proves two writes are byte-identical, and `tests/test_pipeline.py::test_the_same_bundle_twice_produces_the_same_bytes` proves it across a full re-execution. |
| | Caveat, stated rather than hidden: this reproduces the CSV for whatever bundle is in `data/`. The gated bundle is not in this checkout, so the byte-level reproduction of the *final* submission can only be demonstrated after the bundle is unpacked locally. |

## 3. What may not be published

| obligation | enforcement |
|---|---|
| *Keep the submission CSV and local match outputs out of the public repository.* | `.gitignore` excludes `data/`, `out/`, `*.csv` under those paths, `scratch/`, `*.npy`, `*.npz`, `*.parquet`, `SYNTHETIC_BUNDLE.json`, logs and caches. Verified with `git status --ignored` before the commit: no `out/` or `data/` entry is staged. |
| *Never publish match assets or derived data that could reconstruct the restricted match.* | No tracking file, no homography, no Smart Tagging XML, no transition table, no uncertainty table, no label CSV and no manifest containing per-frame labels is committed. The committed tests use a fixture generated in a temporary directory and deleted by `tearDownClass`. |
| | `manifest.compliance` records `restricted_match_assets_in_repository: False` and `submission_csv_committed: False`, and `technical_document` prints those lines from the same dict. |

## 4. Submission contract

| obligation | enforcement |
|---|---|
| *Exactly 199,319 rows, header `frame,label`, one row per video frame.* | `submission.write_submission` writes the header and `enumerate(..., start=...)` — the frame column cannot be anything but `0..N-1` in order. `tests/test_submission.py` asserts the row count against `facts["n_video_frames"]`. |
| *Only `H`, `A`, `D`, `X`; no blanks; no index column.* | Codes are mapped through `official.pm.LABELS`, taken from the scorer rather than restated. `write_submission` raises on a negative code instead of letting `names[-1]` silently become `X`. |
| *Validate with the official validator.* | `run.validate()` calls `scoring.validate_csv` → `official.pm.validate_submission` unchanged; the dashboard exposes the same call. The test suite checks both directions: a valid file passes, and a 40,000-frame fixture is **rejected** at the published length with `row count` in the reason. |
| *Rank on `spellF1`, `macroF1` tie-break.* | `src/evaluation/scoring.py` reports the organizers' keys (`spell_f1_mean`, `macro_f1`, `fragmentation`, `alive_dead_f1`) from `official.pm.evaluate`; nothing is re-implemented. `LABELS`/`TAUS` are read from the scorer, so a rule change upstream shows up here rather than being missed. |

## 5. R3P-specific obligations from the brief

| obligation | where |
|---|---|
| *Use metric distances from the pitch calibration.* | `d = sqrt((105.3·dx)² + (68.0·dy)²)` in `src/possession/evidence.py`; `src/data/atd.py` scales the file's normalised coordinates once, and `tests/test_evidence.py` + `test_alignment.py` pin that no second scaling exists. |
| *Do not double-count evidence.* | §2 of the technical document; `test_pipeline.py::test_the_evidence_channels_all_reach_the_decoder` fails if a configured weight points at a block that does not exist or was not standardised. |
| *Missing ball must not be treated as a dead ball.* | `deadball.missing_weight = 0.55`, the lowest cue weight, plus the `missing_gap_frames = 40` grace and geometric imputation. `MissingBallIsNotDeadTest`. |
| *Smart Tagging must be weak evidence.* | `deadball.tagging_weight = 0.75` and `fusion.weights.tagging = 0.40`, both below the geometric cues. `TaggingIsWeakEvidenceTest`. |
| *Touches, deflections and rebounds must not be read as turnovers.* | Turnover evidence is `continuity` over observations, not `nearest`. `TurnoverIsNotPredictedTest`. |
| *Short possessions must remain possible.* | The duration prior is a soft log-normal cost, not a minimum length. `BlipTest` proves a 3-frame spell is decoded when the emission pays for `log p(d)`. |
| *Hysteresis and restart handling must come from the model, not a post-processing filter.* | There is no smoothing or relabelling step after `decode`. Hysteresis is `A` + the duration prior; restarts are `evidence.restart_modulation`, applied to the `D` row only. `RestartAwareTransitionTest`. |
| *X only outside graded periods; per-half decoding.* | `decoder.decode` iterates blocks; `output.abstain_outside_graded = X` and `decoder.abstain.enabled = false`. `HalfSeparationTest` and `test_only_the_four_labels_appear_and_x_stays_outside_the_graded_window`. |
| *Do not stop after planning; implement, test, fix, report honestly.* | `src/` is a working implementation, 80 tests run and pass, three real bugs found by those tests were fixed in the model rather than in the assertions, and two more were found in the PDF renderer that produces the submission document. |
| *Do not claim R3P beats the official baseline without legitimate evidence.* | No such claim is made anywhere in this repository. The baseline comparison is not run, because the ground truth that would make it mean something is not available for this match. |
| *CLI: `python run_pipeline.py --data-dir data --team-name "TEAM_NAME"`.* | `run_pipeline.py`, with exit codes 0/2/3/4/5/6 documented in `README.md`. |
| *Streamlit dashboard with integrity checks, progress, algorithm info, timeline, H/A/D distribution, transitions and uncertainty, submission generation and validation, technical document export — read-only.* | `app.py`, sections 1–6. Compile-verified; not opened in a browser in this environment because `streamlit` is not installed here, and that limitation is stated rather than glossed. |
| *Synthetic unit tests with fixed seeds for alignment, missing observations, metric distances, tagging interpretation, dead-ball detection, controlled turnovers, half separation, temporal decoding, CSV validation and deterministic reproducibility.* | All ten are in the table in `README.md` and §7 of the technical document. |
| *Pinned dependencies, Windows install notes, gitignore.* | `requirements-r3p.txt`, `README.md`, `.gitignore`. |

## 6. What remains outside this repository's control

1. Running the pipeline on the gated bundle once it is unpacked locally, and only then submitting.
2. Re-checking `RULES.md` and `SUBMISSION.md` for changes before the deadline; the loaders, scorer
   and validator here are the organizers' files, called without modification, so a change upstream
   is a change we inherit rather than fight.
3. Any statement about expected `spellF1`/`macroF1` — which requires the real match, and does not
   exist yet.
